# BoneSystemForNPC 项目文档

版本：1.7.5。作者：Laz。支持对象：人类与龙人 NPC。自有代码采用 MIT。

## 1. 职责与边界

静态外观包负责让游戏加载完整且可识别的模型、材质、物理与部件；本项目在模型就绪后，
为对应 NPC 应用 BoneSystem 骨架、脸部隐藏和绑定，并读取差分管理器保存的默认预设。
不修改玩家装备、NPC 装备表、武器、网络数据，也不创建原本没有加载的装备部件。

外观能被识别不等于其骨链适合任何 NPC。龙人额外适配仅在种族、骨架类型和实际拓扑通过后执行，
不按照角色姓名白名单放行，不将人类外观自动推广到其他种族。

## 2. 工程组成

| 目录 | 职责 |
| --- | --- |
| `src/lua` | 28 个开发单元，按 manifest 顺序合并为单个 chunk |
| `src/bridge` | 启动适配器与私有 Lua 状态引导 |
| `src/forefoot` | 宿主结构校验、当前实例前掌修正和安全资源交接 |
| `reframework/autorun` | 由开发单元生成的正式安装脚本 |
| `assets/natives` | 私有小指约束资源，不覆盖游戏共享约束 |
| `vendor/reframework` | 上游插件 API 头文件与原许可证 |
| `tools` | 源码合并、原生编译及打包 |
| `docs/licenses` | 随分发保留的第三方许可证 |

开发单元不是独立的 require 模块，拆分不新增运行时读文件或调度。注释描述职责、前置条件、
对象归属和生命周期；公开正式源移除自有说明注释，保留代码缩进与名称，不做混淆。

## 3. 原版 BoneSystem 接入

`BSFNStockBridge.dll` 在启动或脚本重载时校验原版 BoneSystem 26.2.10.2 的文件哈希及关键入口。
它重新取得当前私有 Lua 状态，在锁内执行引导，定位原始函数闭包，并在该状态运行 BSFN。
不修改 BoneSystem.dll，不分发其内嵌脚本，不跨重载缓存私有状态指针。失败时恢复栈并释放锁。

普通调用使用原作者的 `fix_bone`，第三参数保持 nil。启动桥没有新增帧或场景 Hook。
BoneSystem 的严格身份检查与龙人辅助器的游戏结构检查是两个独立边界，不应混为一个版本开关。

## 4. 三种运行场景

### 4.1 普通 NPC

NPC 更新入口注册对象，现有 UpdateMotion 回调处理已登记项目。先排除主角与联机猎人，
再按已有专属配置或 Body/Chest 对象编号匹配 BoneSystem 字典。未命中结果有会话缓存；
已完成的对象走快速跳过，不反复扫描套装目录或重设骨骼。

尚未就绪目标使用既有 0.1 秒就绪检查。真正提交前再次比较模型签名和对象身份。
GUI050000 全屏任务菜单通过生命周期锁存暂停工作，冻结工作时钟，不销毁已应用对象；
普通对话不因此暂停，临时子面板变化也不会提前恢复。

### 4.2 艺术馆

独立的 EventModelSetupper 完成态入口通过最终装备对象解析外观；候选和未命中缓存与普通 NPC 分离。
不把艺术馆暂态对象带回正常场景，不在普通游玩中持续执行艺术馆扫描。

### 4.3 任务结算

QuestClear 动作的 WAIT 阶段负责首次骨架与差分应用；最终脸部槽位就绪后补做脸部隐藏和绑定。
结算专用的面部关节传递只允许面部白名单，排除 Head、Neck、根、身体和武器，不改变动作速度、时长或根位移。
动作退出、加载、代际/对象/骨架变化或错误时停止；没有可靠 WAIT 入口时不晚写全身骨架。
龙人额外腿部、小指、前掌修正不混入艺术馆或结算路径。

面部尚未生成时保留当前结算动作的有界待办。WAIT 和 MotPhase=NONE 只等待，
不消耗实际面部探测次数；进入可处理阶段后先快速检查四次，其后以至少 0.05 秒工作时钟间隔检查。
阶段变化允许立即检查，成功后停止。Face 已具备材质而绑定载体尚未就绪时，
仅补做一次关闭骨架与表情绑定的隐藏调用，随后等待原面部绑定流程，不重复应用全身骨架。

动作原生更新返回 END，或触发原有退出/失效条件时，立即撤销待办与表情转接。
60 秒工作时钟或 1200 次实际检查为异常兜底，并非保证等待到时限才退出。
原生返回值不被修改；不会重新启动动画、延长动画或改变根位移。
最多保留八条标量结算摘要，不在摘要中保留对象引用，不自动写磁盘。

结算动作、角色根、Motion、Face、部件及表情驱动的跨回调身份使用 `get_address()` 返回的
原生地址标量，不使用 Lua 包装对象的字符串。包装被回收后重建但原生对象未变时，继续原待办；
原生地址不可确认时跳过，不回退到包装字符串，也不从保存的地址重新构造对象。
地址本身不是生命周期证明：仍需同时通过当前动作、阶段、场景代际、对象归属和骨架构造计数校验。
END/退出清除当前动作记录，真实复用同一地址的后续动作重新建立状态，不能沿用旧面部绑定。

面部重试沿用上述有界时间和节流机制；计数在已有检查中刷新，不增加诊断扫描或持续日志。
原生脸隐藏及表情同步使用同一份确认过归属的面部驱动，任一必要身份变化即停止旧转接。

## 5. 加载与对象生命周期

场景开始只标记代际和过渡状态，随后在安全回调隔离上一场景登记项。Loading 期间不进行普通应用。
配对的结束证据与新场景有效样本允许恢复；同场景快速旅行使用黑屏配对结束信号，不能被较早 load-end 替代。
释放隔离引用后恢复普通工作；重复开始、旧对象迟到或身份复用不能复活上一代项目。

所有龙人待办属于现有登记项和 scene/dictionary generation，复用菜单暂停、TTL、所有权校验和移除机制。
短期重试后转低频就绪检查，成功清除待办；硬错误或已失效对象不进入无限重试。
没有独立龙人全场扫描、额外帧回调或磁盘轮询。

## 6. 龙人修正

### 6.1 分类

先满足普通 NPC 与外观匹配条件，再读取原生 Species、SkeletonType 并检查源/目标骨链。
NML 与 SML 分别处理普通、小型龙人，男女不采用两个人工名单。人类只经历轻量分类，
不会创建额外骨骼待办；未知种族、缺标签或拓扑不兼容时不强行修正。

### 6.2 腿部、小指与前掌

- 腿部：等待原生 IK 链与目标骨架提交后适配当前实例，不施加固定脚角补偿，也不移动角色根。
- 小指：校验无名指/小指三节骨链和有限、归一的绑定四元数，不要求两指绑定旋转相同或为单位旋转。
  追加六条原生相对旋转约束，保留小指绑定姿态并跟随无名指相对基准的变化。保留所有原层和骨骼位置、长度；
  后续动作由游戏处理，不在 Lua 中逐帧抄写手指。失败只撤回自己创建的尾层。
- 前掌：只处理 Body 实例的左右 Instep/Toe 四项映射，恢复对应局部绑定姿态；不改 Foot、IK、根或共享骨架。
  只在首次成功接管时执行，不持续覆盖引擎姿态。

私有 `WyverianPinky_DSG.jcns.102` 位于新增路径，只有命中并通过校验的替换龙人会挂载它。
DSG 为首个适配模型标记，真正兼容条件是骨链与绑定基准，不是外观显示名称。

前掌适配按 BODY 组件实际状态判定，不能仅因存在组件就跳过：

- 没有活动或动态动作库且关节已构造的 Motion 可共存；活动动作库和独立 CustomSkeleton 重建仍跳过。
- 现有 JointConstraints 层保留不变。原生读取器在 Scene 锁内核对所有权、资源就绪和已验证的资源布局。
  已识别的普通约束写入脚骨则跳过；非脚骨约束可以继续。
- 原生确认有效 owner 且未指定资源的空层返回 34，继续检查后续层；已指定但未加载完返回 2，沿用就绪重试。
  空层不代表后续层安全，也不等同于资源加载失败或未知格式。
- General SC 类型 144/146/148 按兼容策略允许共存，报告标记 `SC_allowed_unverified`。
  这不是已证明其不写脚骨；其他未确认格式和已识别写脚骨的普通约束仍拒绝。

约束读取的 managed 类型、更新函数实际地址、owner/资源字段和完整机器码窗口必须通过检查。
结果只在首次适配时使用；成功后不持续扫描层或监控其他 Mod 后续赋值，不保证处理独立换骨或持续写脚的外观。

### 6.3 原生资源交接

腿部 ResourceHolder 与小指新 Layer 由 C 插件 SDK 在单次调用内创建、持有、设置、释放。
新对象不进入 Lua sol 包装缓存，不跨场景缓存。资源初始引用、holder、layer 引用分别配对。
调用使用非阻塞 Scene 锁，锁忙返回既有低频重试；提交前再次核对场景、角色和组件归属。
Single 方法参数/返回按 SDK invoke 的 double 槽位传递，与字段实际 float 布局区分。

## 7. 游戏结构兼容性

不以 EXE 编译时间戳或精确 SizeOfImage 决定兼容性。只要必要证据仍兼容，版本信息变化可继续工作。
验证包含 x64 PE/节区边界、当前页权限与镜像归属、八处既有代码窗口、十五段布局证据、
三个 Joint setter 的 SDK 实际地址，以及场景加锁/解锁导入身份。
布局证据覆盖绑定姿态的旋转、位置、缩放字段及宽度，也覆盖 Joint 列表长度、步长和归属；
仅验证表指针、外层步长或数值范围不能证明表内字段仍然相容。

关键代码、地址、布局或依赖接口改变时，或无法确认这些证据时，跳过龙人额外修正；
不连带关闭普通 BoneSystem 接管。校验不靠试写目标或尝试未知锁来判断安全。
这不是跨版本全自动重定位：即使新版本实际安全，必要证据已变而无法确认时也会拒绝。

验证首次需要时执行，成功和失败均在进程内缓存；之后只读取结果，不新增帧扫描或重复导入解析。
兼容性缓存不保存 NPC、Joint、ResourceHolder 或场景实例。

## 8. 差分与配置归属

自动接管按照实际 Body 编号读取 BoneSystem 和差分配置，不根据 ZIP 名猜测外观。
识别男猎人装备 `ch02` 与女猎人装备 `ch03`，两者共用现有索引、加载隔离、就绪重试及应用后快跳路径。
配置读取成功不等于模型已命中；缺少对应配置的装备仍使用未命中缓存，不反复扫描。
NPC原脸及其他模型前缀不作为猎人装备自动接管，玩家身份排除始终先于装备匹配。
这不改变装备表、NPC性别或动作Core，也不保证任意外观资源自身完整。
默认预设、普通分组、全局隐藏按顺序合并；全局隐藏只贡献关闭状态，不运行玩家血量等变身条件。
材质按名称寻找实际载体，允许头部和身体合并，但不恢复已被静态删除的部件。

私有合并模型仍可能保留某个装备槽位编号；这时模型文件虽私有，骨架/差分依赖仍属于那个槽位。
单独安装另一槽位的同名外观不会自动重定向这些读取。

用户设置与运行索引位于 reframework/data，均由运行时维护，不随包附带。
旧专属 Targets 的兼容读取保留，但发行不提供模板，也不主动删除用户已有文件。

## 9. 性能与维护约束

初始化验证、首次适配和游戏执行约束都有成本；高面数、高清贴图及复杂物理仍会增加 CPU/GPU/显存负担。
完成后的额外骨骼待办应为空，不能以持续写姿态掩盖加载或生命周期错误。
原生资源错误日志每进程有界，诊断不读取已释放对象。公开版不会自动启用持续调试日志。
修改运行时应保留分支边界、引用配对和失败关闭语义；构建方式见 BUILD_zh.md。

结算面部延迟就绪时会比立即放弃多执行有限检查，只在对应结算动作存活期间发生。
普通游玩、艺术馆及龙人修正的调度不因此增加扫描或回调；既有结算表情转接仍有逐帧成本，
不能将无新增普通扫描表述为本 Mod 或所有外观完全没有性能成本。
原生地址读取仅位于现有结算回调与表情传递中，存在少量接口调用成本；没有结算动作时
不因此新增普通 NPC 扫描、目录读取、持久对象引用或等待任务。
